# 数据源配置帮助（商家门户「数据源」面板）

本帮助说明商家门户顶栏 🧩 **数据源** 入口（提示词面板旁）怎么用：把店面的「商品 / 政策」数据从内置演示数据切到你的远端商品目录。设计全文见 [接入系统标准化设计.md](接入系统标准化设计.md)；后端适配器实现见 `examples/retail/api/remote_backend.py`。

> 适用前提：本面板只动「读路径」（商品搜索、商品详情、政策问答）。购物车、订单、用户偏好、配送、结算披露等**写路径始终走本地 Mock**（混合模式），溯源门控与暂存审批不被绕过——远端目录再怎么配，演示数据永远是兜底。

---

## 1. 两种适配器

| 适配器 | 含义 | 何时用 |
|---|---|---|
| `mock-local`（默认） | 用仓库内置的 87 个 ACME 商品 + 政策，纯演示 | 默认；不想接外部系统 |
| `remote-catalog` | 商品 / 政策读路径转发到你的远端 REST 目录（只读） | 想让 Agent 搜/答你自己的商品池 |

选 `remote-catalog` 后，下方出现「连接配置」表单。

---

## 2. 连接配置字段

| 字段 | 说明 | 备注 |
|---|---|---|
| **接入点地址 Base URL** | 你的远端商品目录根地址，例如 `http://127.0.0.1:8000` | 必填（留空则适配器直接降级、全程走本地） |
| **API Key** | 远端目录的鉴权 Key | 只写不回显，保存在 API 侧（已 gitignore）；留空保持已存 Key |
| **超时（秒）** | 单次请求超时，默认 5s | 网络慢可调大 |

填完先用 **测试连接** 探一下（`GET {BaseURL}/health`），看到「正常 · N ms」再 **保存并生效**。保存即重建两个 Agent，此后顾客问商品 / 政策就从你的远端目录取。

---

## 3. 远端目录要实现的端点契约

`remote-catalog` 适配器会向你的 Base URL 发三个 GET 请求（**只读、无写**）：

| 方法 & 路径 | 用途 | 适配器怎么用返回 |
|---|---|---|
| `GET {BaseURL}/health` | 存活探针 | 任意 2xx 即视为健康（熔断半开探活用） |
| `GET {BaseURL}/products?q=<关键词>` | 商品搜索 / 详情 | 支持 `?q=`，见下方字段映射 |
| `GET {BaseURL}/policies?q=<关键词>` | 政策检索 | 见下方字段映射 |

### 3.1 字段宽容映射（重点）

适配器做**宽松字段映射**：认识常见别名、缺字段用协议默认值、多余字段直接丢弃。你不用严格对齐我们内置 demo 的字段名。

**商品记录**（`/products` 返回的数组元素，或包在 `products` / `items` / `results` / `data` 键下均可）：

| 协议字段 | 接受的别名（任选其一） | 是否必填 | 缺省 |
|---|---|---|---|
| `product_id` | `sku` / `product_id` / `id` | ✅ 必填（缺则整条丢弃） | — |
| `title` | `item_name` / `title` / `name` | ✅ 必填 | — |
| `price` | `price`（浮点）或 `price_cents`（÷100） | 否 | 0.0 |
| `brand` | `brand_name` / `brand` | 否 | 空 |
| `rating` | `rating`（0–5，越界忽略） | 否 | 空 |
| `review_count` | `review_count` | 否 | 空 |
| `category_tags` | `category_tags`（数组）→ 标签 | 否 | `[]` |
| `stock_count` | `stock_count`（>0 视为有货） | 否 | 视为有货 |
| `currency` | `currency` | 否 | `USD` |
| `image_url` | `image_url` / `image` | 否 | 空 |
| `category` | `category` | 否 | 取首个 tag |
| `short_description` | `short_description` / `blurb` | 否 | 空 |
| `attributes` | `attributes`（字符串字典） | 否 | `{}` |
| `long_description` / `specs` | `long_description` / `description` / `details`、`specs` | 否（详情用） | 空 |

**政策记录**（`/policies` 返回的数组元素，或包在 `policies` / `items` / `results` / `data` 键下均可）：

| 协议字段 | 接受的别名 | 是否必填 |
|---|---|---|
| `policy_id` | `policy_id` / `id` | ✅ 必填 |
| `title` | `title` / `name` | ✅ 必填 |
| `content` | `content` / `body` / `text` | ✅ 必填 |
| `category` | `category` | 否 |

> 想看一套现成「异构字段」样例，直接看 `examples/retail/api/remote_demo.py`：它刻意用 `sku` / `item_name` / `price_cents` / `category_tags` / `stock_count` 这类字段，正是为了验证宽松映射。

## 4. 用内置模拟系统自测（推荐先跑这个）

仓库自带一个**模拟第三方商品系统** `GET /api/demo-remote/*`（挂在同一个 API 服务上，端口同 API），字段刻意异构，用来零成本验证全链路：

| 端点 | 内容 |
|---|---|
| `GET /api/demo-remote/products?q=<词>` | 一批虚构远端商品（NorthRim / Hearthly 等，本地目录没有） |
| `GET /api/demo-remote/policies` | 运输 / 退货 / 保修政策 |
| `GET /api/demo-remote/health` | `{status, service}` 存活探针 |

**自测步骤**：
1. 数据源面板选 `remote-catalog`；
2. Base URL 填 `http://127.0.0.1:<你的API端口>/api/demo-remote`（API 默认 8000，本机变体 8001）；
3. 点 **测试连接** → 应「正常」；
4. 点 **保存并生效**；
5. 去店面问「有没有 NorthRim 的帐篷」，Agent 应返回远端商品（证明读路径已转发远端）。

**故障注入**：任意端点加 `?fail=1` 返回 500。例如把 Base URL 指向一个会持续 500 的地址，连续 3 次失败后面板会黄标「已降级到本地数据」（见第 5 节）；也可直接 `GET /api/demo-remote/products?fail=1` 体验单次失败回退。

> ⚠️ 生产部署建议关掉这个模拟路由（设计稿 S2 预留了 `DEMO_REMOTE_ENABLED` 之类开关），避免暴露内部异构样例。

---

## 5. 健康降级（演示永不中断）

- 连续 **3 次**远端读取失败 → 熔断器打开，读路径自动回退到本地 Mock（面板黄标「已降级到本地数据」），业务不中断；
- 降级期间每 **30 秒**探一次 `{BaseURL}/health`，首次成功即恢复转发；
- 恢复内置数据：点面板底部 **恢复内置数据**，即切回 `mock-local`（删 `data/backend-override.json` 对应覆盖）。

---

## 6. 安全与配置落盘

- API Key **只写不回显**，保存在 API 侧 `data/backend-override.json`（已 gitignore），永不进版本库；
- 连接配置同样落 `data/backend-override.json`，**请勿提交**；
- API 仅绑定 `127.0.0.1`，绝不暴露公网；远端目录请放在可信网络内；
- 模型调用与远端目录调用是两套独立凭证，互不相干。

---

## 7. 排错速查

| 现象 | 原因与解法 |
|---|---|
| 保存后顾客仍答本地商品 | 没点「保存并生效」；或 Base URL 填错导致立刻降级——看面板「当前生效」是否 `remote-catalog` 且无黄标 |
| 测试连接失败 | Base URL 不可达 / 端口错；确认远端服务在跑；`?fail=1` 会故意失败 |
| 面板黄标「已降级」 | 远端连续 3 次失败，已回退本地；修好远端后等 ≤30s 自动恢复，或点「恢复内置数据」再重配 |
| 商品能搜到但字段缺（无图 / 无品牌） | 远端记录缺该字段或用了未识别的别名——对照第 3.1 节别名表补齐 |
| 切回英文后商品变回 ACME | 正常：英文侧是上游原始演示数据；中文侧即你的远端目录（若 locale=zh） |
