# 本项目与上游差异说明（commerce-agents-zh vs anthropics/commerce-agents）

> 目的：精确说明本中文化发行版相对上游英文项目**改了什么、新增了什么、两者如何解耦**，便于审计、复用与回退。
> 逐文件修改的权威清单见 [NOTICE.md](../NOTICE.md)；本文是其结构化摘要。

## 0. 一句话结论

本仓库是上游项目的**扩展发行版**：核心 Agent 逻辑（推理-行动-观察循环、技能按需加载、工具契约、安全护栏、Backend 抽象）原样保留；我们在其外"套了四层"——

1. 中英双语化（i18n 层 + 数据/文案汉化）
2. 三个运行时配置面板（模型 / 提示词 / 数据源）
3. 数据源适配器注册表（远端只读 + 熔断降级）
4. Agent 接入面（AGENTS.md 手册 / `agentctl` CLI / MCP 服务器）

**所有新能力均为新增文件或"覆盖式"扩展，不重写上游逻辑**；仅有 4 个上游核心文件做了最小、可逆的默认值/模板改动（见 §3.1），全部登记于 NOTICE.md。

## 4. 解耦机制（为什么"改得少"）

1. **覆盖即配置，不重写默认值**：模型 / 提示词 / 数据源三块写一份覆盖 JSON（`model-override.json` / `prompt-override.json` / `backend-override.json`，均 gitignore，绝不提交），由现有 settings 模块加载；上游 config 默认值与提示词构建代码零改动（除 §3.1 那 4 处刻意默认值）。
2. **适配器走注册表，不硬编码**：连接器把 `MockRetail()` 硬编码实例化换成 `BackendSwitch` 包装 + 适配器注册表；`active=mock-local` 返回的**就是原 MockRetail，行为逐字节一致**。`RemoteCatalogBackend` 实现上游已有的 `StorefrontBackend` 抽象类——是"plug in"，不是"改它"。
3. **提示词覆盖复用上游机制**：override 功能地基是上游 `_static_system` 每轮读取机制，我们**明令不得重构**，只是利用它。
4. **双语层**：英文侧 = 上游逐字节；中文侧 = 新增。切到 English 即运行原项目内容。

## 5. "零配置行为"的如实说明

- 英文 locale = 上游逐字节一致 ✅
- `mock-local` 数据源 = 原 `MockRetail` ✅
- Agent 逻辑、工具契约、安全护栏、Backend 抽象 = **未改** ✅
- **但默认模型被刻意换成 `gpt-5.5`**（§3.1），并非上游默认——这是发行版的有意默认，可在模型面板或 3 个 `config.py` 改回。
- 因此"不配置时行为 == 上游"在**架构与机制**上成立，在**默认模型名**上不成立（已文档化、可逆）。

## 6. 回退到纯上游

- 不依赖本发行版新增能力时：删掉覆盖 JSON（本就 gitignore）、把 §3.1 的 4 处还原、停掉 §2 新增端点即可；或直接 `git checkout` 上游对应文件。
- 中文化本身无需回退代码：切到 English 即原项目内容。
